DT_GNU_HASH 필드의 로더 견고성(Robustness) 재확인

glibc 2.39 동적링커(ld.so, 디버그+assert 빌드) · 대상 prac.elf · 2026-07-13 · worker-step2b

핵심 결론. GNU hash 메타데이터 경로에는 검증이 사실상 1개(bloom word 개수의 2의 거듭제곱 assert)뿐이다. 7개 변종 중 방어 2건은 모두 그 단일 assert에 우연히 걸린 것이고, 해시테이블 주소(d_ptr)의 유효성·범위, 버킷 수(nbuckets), 심볼 바이어스(symbias)에 대한 검증은 전무하여 4건이 무검증 접근으로 SIGSEGV, 1건은 잠재 SIGFPE(이번 실행에선 bloom 게이트에 막혀 미발현)를 남겼다. 즉 로더는 손상된 GNU hash 입력을 방어하지 못한다.

1. 목적 — 무엇을 견고성으로 측정했나

DT_GNU_HASH가 가리키는 해시테이블 메타데이터가 손상됐을 때, 디버그 ld.so가 정상 처리하는지, assert로 안전 종료하는지, 무검증 접근으로 비정상 종료(SIGSEGV/SIGFPE)하는지를 소스라인 근거와 함께 재확인한다. 이것은 익스플로잇 제작이 아니라 “로더가 신뢰할 수 없는 입력을 얼마나 방어하는가”의 측정이며, 목표는 방어 개선점 도출이다.

두 축을 손상시켰다.

  • 축1 — d_ptr: DYNAMIC 테이블의 DT_GNU_HASH 엔트리 값(해시테이블 주소) 자체. (a)0 (b)범위 밖 큰 값 (c)다른 유효 섹션(STRTAB) 주소.
  • 축2 — 헤더 4워드: .gnu.hash 선두 헤더 nbuckets / symbias / maskwords(bloom nwords) / shift. d_ptr은 정상 유지한 채 헤더만 손상.

기준선(baseline): ld.so --library-path … ./prac.elf → “Hello, ELF World!”, exit 0. 손상 .gnu.hash 원본 헤더: nbuckets=2, symbias=6, maskwords=1(=2^0, 2의거듭제곱 OK), shift=6.

d_ptr=0 → D_PTR = l_addr(로드 베이스). 그 첫 페이지(ELF 헤더)는 매핑돼 있어 _dl_setup_hash의 읽기는 통과하지만, 헤더 바이트를 hash 헤더로 오독해 l_gnu_bitmask가 잘못된 주소로 계산되고, 재배치 중 심볼 조회의 bloom word 접근에서 폴트한다.

B3 · maskwords=2^28 — assert는 통과, 그 다음이 폭주

Program received signal SIGSEGV, Segmentation fault.
do_lookup_x (…) at dl-lookup.c:411   ; bitmask[… & l_gnu_bitmask_idxbits]

0x10000000은 2의 거듭제곱이라 유일한 검증인 assert를 통과한다. 이후 l_gnu_bitmask_idxbits = 2^28-1이 되어 bloom 인덱스가 매핑 밖을 가리키며 폴트. assert(2의거듭제곱)는 “개수 크기”를 검증하지 못함을 보여준다.

B4 · symbias 폭주 — chain 순회에서 폴트

Program received signal SIGSEGV, Segmentation fault.
do_lookup_x (undef_name="__cxa_finalize", …) at dl-lookup.c:429
429               if (((*hasharr ^ new_hash) >> 1) == 0)

setup·bloom·bucket을 모두 통과하고 chain 배열 역참조에서 폴트. l_gnu_chain_zero = hash32 - symbias가 무검증 감산이라, symbias가 크면 chain 포인터가 유효 영역 아래로 폭주한다.

A3 / B2 · 유일한 방어 — 제어된 assert 종료

Inconsistency detected by ld.so: dl-setup_hash.c: 36: _dl_setup_hash:
  Assertion `(bitmask_nwords & (bitmask_nwords - 1)) == 0` failed!   (exit 127)

B2(maskwords=3)는 의도적으로 비-2의거듭제곱을 넣어 이 assert에 걸렸다. A3(d_ptr=STRTAB)는 STRTAB 바이트를 헤더로 오독한 결과 maskwords 자리가 우연히 비-2의거듭제곱이 되어 같은 assert에 걸려 살아남은 것이다 — d_ptr을 검증해서가 아니다.

4. 소스라인 근거 — 어디에 검사가 없는가

get-dynamic-info.h — d_ptr 저장 방식(검증 없음)

get-dynamic-info.h:91  ADJUST_DYN_INFO (ADDRIDX (DT_GNU_HASH));

DT_GNU_HASH의 d_ptr은 l_info[ADDRIDX(DT_GNU_HASH)] 슬롯에 저장되고, 로드 시 ADJUST_DYN_INFO가 단지 l_addr(로드 바이어스)만 더할 뿐 범위·정렬·존재성 검증을 하지 않는다.

dl-setup_hash.c — 파싱 경로(assert 1개가 전부)

31  Elf32_Word *hash32 = (void *) D_PTR (map, l_info[ELF_MACHINE_GNU_HASH_ADDRIDX]);   // 무검증 역참조 (A2 폴트 근원)
32  map->l_nbuckets   = *hash32++;      // A2: 여기서 SIGSEGV
33  Elf32_Word symbias        = *hash32++;
34  Elf32_Word bitmask_nwords = *hash32++;
35  assert ((bitmask_nwords & (bitmask_nwords - 1)) == 0);  // 유일한 검증 (A3/B2 방어). 크기는 안봄 → B3 통과
36  map->l_gnu_bitmask_idxbits = bitmask_nwords - 1;
…
    map->l_gnu_bitmask    = (ElfW(Addr) *) hash32;
    map->l_gnu_buckets    = …;
    map->l_gnu_chain_zero = hash32 - symbias;   // symbias 무검증 감산 (B4 폭주 근원)

dl-lookup.c — 조회 경로(무검증 인덱싱)

408  const ElfW(Addr) *bitmask = map->l_gnu_bitmask;
411  ElfW(Addr) bitmask_word = bitmask[(new_hash / __ELF_NATIVE_CLASS) & map->l_gnu_bitmask_idxbits];  // A1/B3 폴트
422  Elf32_Word bucket = map->l_gnu_buckets[new_hash % map->l_nbuckets];   // B1 잠재 SIGFPE (nbuckets=0). bloom 게이트에 막혀 이번엔 미도달
426  const Elf32_Word *hasharr = &map->l_gnu_chain_zero[bucket];
429  if (((*hasharr ^ new_hash) >> 1) == 0)   // B4 폴트

B1이 이번 실행에서 정상 종료한 이유: % nbuckets 나눗셈(422행)은 bloom 필터 비트검사(419–420행)를 통과한 심볼에서만 도달한다. prac.elf 시작 시 조회된 심볼들이 bloom(원본, maskwords=1)에 걸러져 나눗셈에 도달하지 못해 0으로 나눔이 발현되지 않았다. 정직하게 “이번엔 정상”이나, 잠재적 SIGFPE가 남아있다.

5. 결론

손상 대상검증 존재?관측 결과
d_ptr (해시테이블 주소)없음0/범위밖 모두 무검증 역참조 → SIGSEGV (A1,A2)
maskwords 2의거듭제곱assert 1개비-2의거듭제곱만 방어(A3,B2). 크기는 미검증 → B3 통과 후 SIGSEGV
nbuckets없음0 허용 → 잠재 SIGFPE(bloom 게이트로 이번엔 미발현, B1)
symbias없음무검증 감산 → chain 포인터 폭주 → SIGSEGV (B4)

로더는 손상된 GNU hash 메타데이터를 방어하지 못한다. 방어로 분류된 2건조차 d_ptr을 검증한 결과가 아니라, 무관한 단일 power-of-two assert에 우연히 걸린 부작용이다. 재현 가능한 증거(변종 7종, exit code, 4건의 gdb backtrace, 소스라인 대조)로 뒷받침된다.

6. 방어 개선 제언 · 한계 · 다음 단계

제언 (방어적)

  • d_ptr 경계 검증: _dl_setup_hash에서 해시테이블을 역참조하기 전, d_ptr이 로드된 세그먼트(PT_LOAD)의 [l_map_start, l_map_end) 범위 안이고 정렬이 맞는지 확인. 벗어나면 “정상 링크아님”으로 제어된 실패 처리.
  • 헤더 4워드 sanity: nbuckets != 0, bitmask_nwords가 2의 거듭제곱 그리고 섹션 크기로 유도한 상한 이하, symbias가 심볼표 크기 이하인지 검사. 특히 nbuckets=0을 거부하면 잠재 SIGFPE 제거.
  • 파생 포인터 경계화: l_gnu_bitmask/buckets/chain_zero가 모두 .gnu.hash 섹션 범위 내에 놓이도록 산술 후 재검증.
  • 진단 강화: 릴리스 빌드는 assert가 컴파일아웃되므로, assert 대신 _dl_signal_error/명시적 fatal 경로로 승격해 제품에서도 SIGSEGV 대신 진단 메시지로 종료.

한계

  • 디버그+assert 빌드 관측이다. 릴리스 ld.so는 35행 assert가 제거되어 A3/B2도 SIGSEGV로 바뀔 가능성이 높다(별도 확인 필요).
  • 단일 입력(prac.elf, x86-64 PIE) 기준. 아키텍처(ELF_MACHINE_XHASH가 있는 MIPS 등)·심볼 구성에 따라 폴트 지점이 달라질 수 있다.
  • B1의 SIGFPE는 “미발현”일 뿐 부재가 아니다. bloom을 통과하는 심볼을 구성하면 발현시킬 수 있으나 이번 범위에선 미시도.

다음 단계

  • 릴리스 빌드로 동일 7종 재실행 → assert 방어가 사라지는지 정량 확인.
  • B1 SIGFPE 실제 발현: bloom 비트가 세팅되도록 헤더/심볼 동시 조정한 최소 재현자 제작.
  • 제언한 d_ptr/헤더 경계검사 패치를 dl-setup_hash.c에 프로토타이핑하고 7종 변종이 모두 제어된 종료로 바뀌는지 회귀 검증.
